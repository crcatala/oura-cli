# Add tags command (enhanced_tag lifestyle events)

Expose the /v2/usercollection/enhanced_tag collection as `oura tags`. Enhanced tags record lifestyle events Oura uses as correlation inputs: standardized tag types (e.g. alcohol, caffeine, travel, illness, stress), custom tag types, and freeform text-only tags. Each document carries:

- tag_type_code (string|null; null for text-only tags, "custom" for custom types)
- custom_name (string|null; the custom tag's name when tag_type_code is "custom")
- start_time / start_day (required), end_time / end_day (nullable; duration events)
- comment (string|null; freeform text)

Tags are the key to making other Oura metrics explainable: sleep or HRV anomalies become interpretable when paired with the alcohol/travel/illness tag from the same day. Deliberately implement enhanced_tag only - the legacy /tag collection is superseded by it and is out of scope.

## Design

- Add endpoint key enhancedTag: "enhanced_tag" to ENDPOINTS and client methods enhancedTagRange(start, end); add an EnhancedTag type matching the schema (id, tag_type_code, custom_name, start_time, end_time, start_day, end_day, comment) with no invented fields.
- Register `oura tags` in buildProgram. Window by start_day using resolveDateWindow with --date/--days/--start/--end, following the workouts/sessions event-style pattern rather than makeDailyCommand.
- Table columns: start_day, tag_type_code (fall back to custom_name when tag_type_code is "custom", or "(text)" when both are null), start_time, end_time, comment. Full document preserved in --json.
- Do NOT add a legacy /tag command; if the legacy collection is ever needed, file a separate ticket.

## Acceptance Criteria

- `oura tags --date YYYY-MM-DD` returns tags whose start_day matches; --days and --start/--end windowing behave like workouts/sessions.
- --json output preserves the complete source document; table display falls back to custom_name for custom tags and marks text-only tags.
- Empty window prints "(no data)" without error.
- Unit tests with a redacted fixture covering a standardized tag, a custom tag, a text-only tag, and a duration (multi-day) tag; README command list and CHANGELOG updated; npm test and npm run lint pass.
